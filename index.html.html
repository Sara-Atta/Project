Concept workEnd-to-end pipeline

Concept Work — created as a practice project to demonstrate my skills.

Branch Sales Pipeline

An automated Azure pipeline that merges daily sales files from several store branches into one reporting table.

role: solo — design, build, documentation

Challenge

A retail business receives each branch's sales as a separate Excel or CSV file. Merging them by hand is slow, and totals often don't match between reports.

Action

Built an Azure Data Factory pipeline that picks up new files from Data Lake Storage, cleans them in Databricks with PySpark through raw, cleaned, and trusted layers, and loads a star schema into Azure SQL Database.

Result

Sales from every branch land in one table on a schedule, and rows with missing or duplicate values are flagged before they reach the report.

  • Azure Data Factory
  • ADLS Gen2
  • Databricks
  • PySpark
  • Azure SQL
Concept workData warehouse

Concept Work — built on the public Olist e-commerce dataset.

E-commerce Data Warehouse

A star-schema warehouse that turns nine related e-commerce tables into one model ready for reporting.

role: solo — data model, SQL, load logic

Challenge

The public Olist dataset spreads orders, customers, products, sellers, payments, and reviews across nine files. A simple question like "which category has the most late deliveries?" needs many joins.

Action

Designed a star schema with an order-items fact table and customer, product, seller, and date dimensions. Wrote T-SQL stored procedures to load it, including an incremental load that only processes new orders.

Result

Business questions are answered with short queries against one fact table, and the model connects directly to Power BI.

  • SQL Server
  • T-SQL
  • Star schema
  • Python
  • Power BI
Concept workData quality

Concept Work — built on public NYC taxi trip records.

Data Quality Checker

A reusable Python tool that tests a dataset against validation rules before it enters a pipeline.

role: solo — rules, script, report

Challenge

Raw taxi trip records contain negative fares, zero-distance trips, and drop-off times before pick-up. Loading them as they are breaks every report built on top.

Action

Wrote a Python script that profiles each column, applies validation rules, moves failed rows to a quarantine file with the reason they failed, and writes a short data quality report.

Result

Only clean rows move forward, and rejected rows are kept with their reason, so no data is silently lost.

  • Python
  • Pandas
  • Parquet
  • Jupyter
  • Git
